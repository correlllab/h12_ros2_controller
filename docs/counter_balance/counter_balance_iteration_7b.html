Iteration 7b: controlled recovery, with a movement-regression gate.

The new hardware data confirms active counter motion, near-matched cadence and repeatable return offsets. It also shows harmful movement-phase behavior in ALMI diagonal and FAME sideways. A reliable controller must solve both; a return-only improvement cannot qualify it for deployment.

Recommendation: begin one narrow offline recovery experiment. Do not deploy a stronger full-motion controller, lower the posture weight, extend hold globally or raise authority limits. Confirm the unexpected ALMI diagonal regression separately. Extraction contact remains outside the validated operating envelope.

One first candidate: postfade position-reference recovery

Hypothesis: after movement and the existing fade have finished, a bounded persistent recovery reference can reduce the counter-arm return plateau without worsening base recovery or moving-arm endpoint error.

Keep every moving/fading command identical to unchanged Counter until T+0.5 s. The experiment changes only the posture-only recovery phase. It is not a fix for B2's movement-phase instability, and no benefit can be credited before the intervention starts.

Failure outputs must be defined before hardware

  • Rejected proposal with fresh, valid state: discard the proposed reference increment; propose a measured-position/zero-velocity counter fallback and validate it before publication. Invalidate the recovery state and require explicit re-arming from the resulting accepted buffer. Do not resume an accumulated target on the next tick. If that hold itself is invalid, request the verified external stop path rather than publishing an unchecked pose. This requires an explicit candidate fallback contract; do not assume the current fallback already proves all these conditions.
  • Stale/invalid state or operator STOP: invalidate recovery and latch the supervisor's stop path. Do not construct a new hold from untrusted measurements, retain nonzero recovery velocity, or silently re-arm. Specify the actual publisher-buffer and relay outputs and verify them against the approved safety contract; “freeze integration” alone is insufficient.
  • Missed deadline with fresh state: skip elapsed updates and issue at most one validated nominal step. For a longer foreground stall, an independent freshness/command-lease mechanism must stop or safely hold the last intent even while the asynchronous publisher continues its heartbeat. A continuously republished buffer is not proof of a fresh control decision. Until this behavior is verified, candidate hardware is blocked.
Same gains do not mean same torque authority. Persistent position error can increase motor PD effort even if joint velocity/excursion limits are unchanged. Bound reference-to-measurement lead, per-step motion, acceleration and estimated total PD-plus-feedforward effort. Feedforward clipping alone is not a total torque limit. Choose and document these commissioning bounds before tests; this report does not invent safe numerical values from 12 trials.

Falsifier: reject the mechanism if verified execution fails to reduce the return plateau. Reject its usefulness if joint return improves but terminal body drift, gyro, endpoint tracking or safety margins worsen. Do not select a candidate solely because the elbow reaches its starting angle.

Implementation and verification order

  1. Freeze the baseline. Current campaign code/config and raw identities remain the control. Keep an opt-in candidate config; no default behavior changes. Reproduce all six current pairs and quality flags from the retained analysis.
  2. Add only missing phase-quality diagnostics. Separate onset-only warnings from operator aborts; check continuity for each reported hold/terminal window. Mark START bookkeeping and whole-loop stalls separately. Do not bypass runtime freshness or external safety checks.
  3. Implement and unit-test the recovery seam offline. Assert identical pre-transition commands; no position/velocity discontinuity at transition; no windup or large step after reject, skipped tick or stale observation; correct arm ownership; limits and collision validation of the proposed reference.
  4. Test actuator behavior without assuming nominal velocity delivery. In the existing simulation path, compare unchanged Counter and the recovery candidate at identical initial states, including bounded delay/load sensitivity. Keep physical parameters frozen rather than fitting them to make the candidate win. Record command, local buffer, physics-received command, measured motion and total effort estimates separately.
  5. Run a small sentinel comparison. Cover both policies' diagonal, FAME sideways and ALMI inner-forward. Include full motion, fade and return, and a matched reset repeat where pre-transition traces differ. Any difference before the recovery transition is initial-state/execution variability, not treatment benefit.
  6. Stop or proceed on the declared gates. No candidate advances if it reduces posture offset but worsens recovery, endpoint tracking, effort or constraints. If the same-state/physical response mismatch persists, investigate the actuator/load/interface model rather than increasing gains.
